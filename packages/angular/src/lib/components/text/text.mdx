## Overview

The typography primitive, applied as an **attribute on any element** so your HTML
semantics stay intact. The attribute value is the typeface —
`<h1 uni-text="display-small">` — and `[uni-text]="role()"` binds it dynamically.

With no value, the typeface is inferred from the host element (`h1` →
`headline-large`, `p` → `body-1-long`, `small` → `caption`, `blockquote` → `quote`,
falling back to `title-small`), so plain semantic markup is correctly set with zero
configuration. `color` takes any theme color token; `align`, `nowrap`, `maxWidth`,
and `ellipsis` handle common text layout.

It is a directive, so it stacks with anything else on the element — a layout
attribute or a component's own host — rather than colliding with it:

```html
<div row-layout uni-text="title-small" padding="md">Heading</div>
```

One caveat on that combination: `color` is an input on the layout directives too,
where it means a **container** pair (a background plus its on-color). A single
`color` binding feeds both directives, so the ink and the background resolve to
the same token and the text vanishes. Use `textColor` on a shared element — it
wins over `color`:

```html
<div row-layout uni-text="title-small" color="primary-container" textColor="on-surface-variant">
  Heading
</div>
```

## Accessibility

- Text never replaces your elements — headings stay `h1`–`h6`, paragraphs stay `p`,
  so the document outline is real.
- Type is styling only: pick the element for meaning, the typeface for appearance
  (an `h2` can wear `display-small` without losing its heading semantics).

## Do

- Reach for semantic elements first and let the element-aware defaults set the type

## Don't

- Use `span uni-text="headline-large"` where a real heading belongs
