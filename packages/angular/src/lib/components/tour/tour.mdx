## Overview

Tour sequences one `uni-callout` through a list of steps: spotlight targets,
dim interludes, and interaction gates. A step with `advanceOn` locks Next
until the user performs the gesture on its target — clicks auto-advance
(the gesture is complete), anything else unlocks Next and announces it
through one polite `role="status"` region, so nobody is yanked forward
mid-typing. `active` is a two-way model, so tours are deep-linkable; Escape
or the close button skips and reports the step through `skipped`.

`started` fires when the first step of a run is presented — through `start()`
or a write to `active` — and `finished` only for a run that presented at least
one step. A `start()` issued before `steps` are bound waits for them, so a host
that loads steps from a service and starts in the same turn still opens on the
first one. A step without a `body` renders its title alone, and a one-step tour
draws no progress.

## Targets

A step's `target` is an element, a string, or a function returning an
element, and every shape is resolved when the step presents — never earlier.
A string is an id unless the tour's `resolveTarget` says otherwise; a
controller whose steps name `data-tour` tokens gives it one lookup instead of
pre-resolving every step.

A target that is not in the DOM yet is waited for: the tour watches the
document for `targetTimeout` (2 s by default) and opens the step the moment
the element lands, with the previous step left up meanwhile. That covers a
page that renders in pieces and a click-gated step whose click opens the
panel the next step points into — the click advances before Angular has drawn
the panel. Only a target that never appears is skipped, in the direction of
travel, with a dev warning and a `targetMissing` event (`{ key, index }`) a
controller can log. `targetTimeout="0"` skips at once. An element handed in
that is no longer in the document counts as missing, so a controller that
pre-resolved its elements survives a re-render.

## Accessibility

- Each panel is labelled `"<title>, step <n> of <total>"`; the dots are `aria-hidden` decoration.
- Gate unlocks are announced ("Next available") through a single persistent live region.
- Arrow-key navigation never fires while the user is typing in a spotlit target.
- The close button reads as the skip affordance (`skipLabel`).

## Stepping into a panel

Each step re-shows the callout, so a panel the previous step's click opened —
which entered the top layer after it and would otherwise cover it — ends up
beneath it again, and the next step can point inside the panel. This needs the
panel to be non-modal: a `showModal()` dialog makes everything outside it
inert, which no stacking undoes. For a drawer, that is `[modal]="false"`.

## Do

- Keep tours short and gate only steps whose gesture teaches something
- Handle `skipped`/`finished` and persist them — the tour holds no storage;
  `finished` is only ever reported for a run that actually opened

## Don't

- Point steps at elements that may never exist without handling `targetMissing`
- Span routes in one tour; sequence per page instead
