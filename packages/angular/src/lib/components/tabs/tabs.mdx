## Overview

Tabs organize peer views behind a single switcher. Each `uni-tab` supplies a label and
its panel content; only the selected panel is instantiated, so heavy tab content costs
nothing until visited.

The panel adds no padding of its own: content sits flush against the tablist, and
the spacing around it is yours to set on whatever you project.

The default tokens render underline tabs; a theme that sets `borderRadius: 'max'` and
an `activeColor` gets segmented pills without any component changes.

## Switching panels

A switch is softened rather than cut: the incoming content fades in while the panel
animates from the outgoing content's height to its own, so whatever sits below the tabs
glides instead of jumping. The new content is rendered and interactive from the first
frame; the animation never delays it.

<StoryExample of={Stories.UnevenPanels} />

The timing comes from the `panelMotion` theme option, a named motion primitive (`panel`
by default). Point it at a faster or slower primitive to retune it, or set it to
`undefined` to switch instantly. Under `prefers-reduced-motion` the switch is always
instant.

## Accessibility

- Full WAI-ARIA tabs pattern: `tablist`/`tab`/`tabpanel` roles with wired
  `aria-selected`, `aria-controls`, and `aria-labelledby`.
- Arrow keys move between tabs with selection following focus, wrapping at the ends;
  Home and End jump to the first and last enabled tab.
- Roving tabindex: only the selected tab sits in the tab order; the panel itself is
  focusable so keyboard users can scroll its content.
- The panel animation is skipped under `prefers-reduced-motion`.

## Do

- Use for peer views of the same subject (details, activity, settings)
- Keep labels to one or two words

## Don't

- Nest tabs inside tabs
- Use tabs for sequential steps — that is a stepper
