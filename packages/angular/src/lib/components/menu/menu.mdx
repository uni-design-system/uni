## Overview

Menus can be linked to any component, but it is recommended to use either the `text-button` or `icon-button` component.

Menus are populated by creating an array of Menu Items (`MenuItem[]`) and binding it to the `Menu` component.
Actions are optional as the `Menu` component also emits the clicked menu item via the `menuItemClicked` output attribute.

### Menu Item Interface

An item is either a labeled action, a templated action, or a divider:

```
MenuItem =
  | { label: string; symbolName?: string; action?: () => void;
      variant?: Variant; disabled?: boolean }
  | { template: TemplateRef<T>; context: T; symbolName?: string;
      action?: () => void; variant?: Variant; disabled?: boolean }
  | { divider: true }
```

- `variant` routes through the theme's `menuItem` variants — e.g. `variant: 'warn'`
  renders the item in the theme's destructive tone.
- `disabled` items render with the disabled color and are skipped by keyboard
  navigation.
- `{ divider: true }` renders a `role="separator"` rule styled by the `menu`
  theme options.

## Theme options

Panel chrome and item anatomy are themed via the `menu` and `menuItem`
component entries. The `menu` panel colors (`color`/`border`/`borderRadius`/`shadow`)
fall back to the shared `dropdown` options when unset, so menus follow generic
popovers until a theme deliberately splits them.

## Accessibility

- Full ARIA menu pattern: arrows and Home/End move, first-letter typeahead jumps, Enter/Space activates.
- ArrowDown/ArrowUp on the trigger opens onto the first/last item; focus returns to the trigger on close.
