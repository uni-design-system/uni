## Overview

Menus can be linked to any component, but it is recommended to use either the `text-button` or `icon-button` component.

Menus are populated by creating an array of Menu Items (`MenuItem[]`) and binding it to the `Menu` component.
Actions are optional as the `Menu` component also emits the clicked menu item via the `menuItemClicked` output attribute.

### Menu Item Interface

An item is a labeled action, a templated action, a divider, or a group heading:

```
MenuItem =
  | { label: string; description?: string; symbolName?: string;
      action?: () => void; variant?: Variant; disabled?: boolean }
  | { template: TemplateRef<T>; context: T; symbolName?: string;
      action?: () => void; variant?: Variant; disabled?: boolean }
  | { divider: true }
  | { heading: string }
```

- `variant` routes through the theme's `menuItem` variants — e.g. `variant: 'warn'`
  renders the item in the theme's destructive tone.
- `disabled` items render with the disabled color and are skipped by keyboard
  navigation.
- `description` is secondary text that trails the label on the same line, in
  the theme's `menuItem.descriptionColor`. See [Descriptions](#descriptions).
- `{ divider: true }` renders a `role="separator"` rule styled by the `menu`
  theme options.
- `{ heading: 'Edit' }` names the items that follow, up to the next heading or
  divider. See [Group headings](#group-headings).

## Group headings

A heading names a group of items. The array stays flat: the items from a
heading to the next heading or divider render inside a `role="group"` labeled
by the heading, and items with no heading above them render as before.

The heading is text, not a command. It takes no focus, has no hover fill, is
skipped by arrow keys, Home, End and typeahead, and a click on it does nothing.
A heading with no items under it (the caller filtered them all out) renders
nothing, so a menu can be built with `filter` or `flatMap` without tidying up
after itself. Use a heading in place of a disabled item, which assistive
technology reads as an unavailable command.

Its look comes from the `menu` theme options `headingTypeface`, `headingColor`,
`headingHeight` and `headingPaddingHorizontal`. The padding follows
`menuItem.paddingHorizontal` when unset, so heading and item text align.

## Descriptions

A labeled item can carry a `description` — a few words of secondary text. It
sits on the label's line, pushed to the trailing edge, so the item keeps its
themed height; the menu widens to fit. It is read as part of the item's name,
and typeahead still matches the label only. Reach for a templated item when
the content needs more than one line.

## Theme options

Panel chrome and item anatomy are themed via the `menu` and `menuItem`
component entries. The `menu` panel colors (`color`/`border`/`borderRadius`/`shadow`)
fall back to the shared `dropdown` options when unset, so menus follow generic
popovers until a theme deliberately splits them.

## Accessibility

- Full ARIA menu pattern: arrows and Home/End move, first-letter typeahead jumps, Enter/Space activates.
- ArrowDown/ArrowUp on the trigger opens onto the first/last item; focus returns to the trigger on close.
- A group heading labels its items through `role="group"` and `aria-labelledby`; the heading itself is never a menu item.
