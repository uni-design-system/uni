## Overview

Single choice from a list, on a native `<select>` — platform pickers on mobile,
platform keyboard behavior everywhere. Options are typed generically
(`options: T[]` with `optionLabel`/`optionValue` accessors), and the component
implements `FormValueControl` for the Signal Forms `[formField]` directive. Errors
style the field only after interaction, matching Input.

The value contract is `T | null`: `null` is "nothing selected". A value that no
option stands for — `''`, a stale id — renders as empty too, never as the first
option, and is reported with a dev-mode warning once the options have loaded.

For choosing several, use Multi Select. When the list outgrows ~10 options, or
users know what they're looking for and want to type it, use Combobox — the
value contract is identical (`T | null`, `compareWith`), so the swap is a
template-only change.

## Disabled options

Mark an individual choice `disabled` to show it without offering it — a plan
that needs an upgrade, a date already taken. It stays visible and announced;
the native `<select>` skips it for both pointer and keyboard.

## Accessibility

- Native `<select>`: platform keyboard interaction and mobile pickers for free.
- `label` becomes the accessible name; `aria-invalid` reflects the touched error state.
- Disabled options are rendered and announced, not hidden — removing them would
  make the list lie about what exists.

## Don't

- Bind `''` to mean "nothing selected" — the contract is `null`. The field shows
  empty either way, but `''` is reported as a value outside the options.
