## Overview

The form-bound, **closed-set, single-select** autocomplete: object
`Options<T>`, `FormValueControl<T | null>`, type-to-filter, commit-on-select.
Typing produces a *draft* — a filter, never a value; the value changes only
when an option commits, the field clears, or the model is written from
outside. Select semantics, not search: a real label, a chevron, no magnifier,
nothing submits.

Under ~10 options and no need to type → `uni-select`, the native, zero-JS,
mobile-friendly answer. More options, or users know what they're looking for →
`uni-combobox`. The value contract is identical (`T | null`, `compareWith`),
so swapping one for the other as a list grows is a template-only change — that
is deliberate. For open sets, where typing *creates* values, use
`uni-tag-input` (multi) or `uni-search-input` (queries); for closed multi
sets, `uni-multi-select-dropdown`.

## Usage

<StoryUsage of={Stories.Primary} />

The draft resolves on Enter, Tab and blur: an active option commits; else a
unique exact label match commits; on **Enter only**, a filter narrowed to
exactly one enabled option commits (`alab` + Enter is Alabama without arrowing
down). Anything else reverts the field to the committed label and reports
through `(rejected)` — a combobox never invents a value the user didn't
confirm. A value with no matching option renders an empty field but is
**preserved**: options may still be loading, and the field self-heals when
they arrive.

## Allowing new values

The combobox never commits free text implicitly — typing filters, it never
selects, and a non-matching draft reverts with `(rejected)`. That's the
closed-set contract, and it's what keeps mystery data out of forms. When users
should be able to *create* an entry, make creation an **option**: narrow
matches from `(query)` and, when nothing matches exactly, append a sentinel
`Create "…"` row. Because the sentinel is a real option, every commit path
already works — arrow + Enter, click, and plain Enter once the filter narrows
to it alone. Resolve the sentinel in `(selected)`: mint the entity, add it to
`options`, and write the model; the field self-heals to the new label.

<StoryExample of={Stories.CreateNewValues} />

Blur deliberately does **not** commit the sentinel — blur commits exact label
matches only, so creating something takes an explicit Enter or click the user
can see. If a full create flow is too heavy, listen to `(rejected)` instead
and offer creation outside the control (a toast, an inline button). And if
most values are user-created, the control is the wrong shape — that's an open
set, which is `uni-tag-input`'s contract.

## Suggestion popup

The list renders in the browser's top layer, anchored to the field, so it is
never clipped by a scrolling or `overflow: hidden` ancestor — put this control
inside a card, a table cell or a dialog and the list still escapes the box. The
browser tracks the field itself; the list follows on scroll and resize, and
flips above the field near the bottom of the viewport.

Browsers without CSS anchor positioning keep the older in-flow popup, which
does clip inside such ancestors.

## Theme options

<ThemeOptions componentName="combobox" />

Field chrome — colour, border, radius, focus outline — is **not** duplicated
here. It comes from the `input` entry via `uni-input-box`, so a combobox
restyles along with every other field. `maxVisibleOptions` is a scroll
height, never a cap: a closed-set control must not render a
reachable-by-keyboard-only subset.

## Accessibility

- The input is `role="combobox"` with `aria-expanded`, `aria-controls` and
  `aria-activedescendant` over a `role="listbox"` — the shared
  `ListboxNavigation` contract, learned once across search-input, tag-input
  and time-input.
- Home and End move the caret, never the list, per APG's editable-combobox
  pattern — a field that steals them makes its own text un-navigable
  mid-edit. Nothing is lost: ArrowUp opens on the last option, ArrowDown on
  the first, and navigation wraps at both ends.
- `aria-selected` marks the **committed** option; the active one is carried by
  `aria-activedescendant`. They are different facts, and this control has
  both. The check icon is decorative (`aria-hidden`).
- Disabled options are rendered, announced (`aria-disabled`), and skipped by
  the arrows — hiding them would make the list lie.
- Commits (*"Alabama selected."*), clears, refusals and debounced result
  counts (*"4 results."*) announce through a `role="status"` live region;
  filtering is otherwise silent to a screen reader.
- `aria-invalid` is gated on `invalid && (touched || dirty)`, per the
  library's form-control rule; `ariaDescribedBy` passes through for
  app-rendered errors.

## Don't

- Don't expect free text to commit implicitly — it never does. Offer creation
  as an option instead (see *Allowing new values*); a mostly-user-created set
  is an open set, which is `uni-tag-input`'s job.
- Don't wire `(query)` → filter → `[options]` when the list is already in
  memory — local filtering is the default for a reason. `(query)` is for
  fetching, not displaying.
- Don't use `Escape` to clear: it closes, then reverts. The ✕ and an emptied
  field are the clear paths.
