## Overview

Icons are adaptive svg images. By default they grow to the space allotted to them and
use the current color of the parent element — so a themed control can size its own glyph
through padding, and recoloring the container recolors the icon.

Both defaults can be overridden:

- `color` statically sets the icon color, ignoring `currentColor`.
- `size` sets an explicit square size, for call sites that would otherwise need a
  width/height CSS rule just to size one icon. Bare numbers are px; strings pass
  through, so any CSS length works.

```html
<uni-icon name="search" />
<!-- fills its container -->
<uni-icon name="search" size="20" />
<!-- 20px -->
<uni-icon name="search" size="1.25rem" color="primary" />
```

Leave `size` off wherever the container already defines the box — that is still the
preferred form, and it is what keeps a themed `icon-button` in control of its glyph.

## The icon set

The built-in set is Material Symbols Outlined at weight 300, normalized to a single
`0 -960 960 960` grid so every glyph shares one optical weight. Names are flat camelCase
and grouped by intent — navigation (`menu`, `chevronDown`, `arrowLeft`, `externalLink`),
actions (`search`, `close`, `edit`, `delete`, `share`, `filter`), feedback (`checkCircle`,
`warning`, `alertCircle`, `lock`) and user/system (`profile`, `settings`, `notification`).

`IconName` autocompletes the built-ins while still accepting any name a theme adds
through `createTheme({ icons })`. The set is generated — regenerate it rather than
hand-editing `BaseIcons`.

## Accessibility

- Icons are decorative (`aria-hidden`) — the parent control carries the accessible name.
- Icons come from the theme's `icons` map (masked with `currentColor`); unknown names render nothing.
