`uni-tour` resolves targets when a step presents and waits for ones that render late; `uni-card-group` leaves keys inside a card's content alone, and an option card fills its grid cell.

- **Tour targets** (`tour-and-callout-2026-10-14.md` §2): a step's `target` is now `HTMLElement | string | () => HTMLElement | null`, resolved at present time. A string is an id unless the new `resolveTarget` input — `(ref: string) => HTMLElement | null` — maps it, so a controller whose steps name `data-tour` tokens gives one lookup instead of pre-resolving every step. A target that is not in the DOM is **waited for**: the tour watches the document for `targetTimeout` (default 2000 ms; `0` skips at once) and presents the step the moment the element lands, with the previous step left up meanwhile — a page that renders in pieces, and a click-gated step whose click opens the panel the next step points into, no longer lose steps. Only a target that never appears is skipped, in the direction of travel, with the dev warning as before plus a **`targetMissing`** output (`{ key, index }`) so a controller can log it. An element handed in that is no longer in the document counts as missing rather than anchoring to nothing.
- **`uni-card-group` follow-ups** (`card-group-followups-2026-10-22.md`): the group's arrow, Home and End keys count only when they start on a card's frame — the radio — so a key inside a card's content (the caret moving in an address field on a ship-to card) is the content's, as the card's own Space and Enter already were. And a card that is an option sets `display: grid` on its host, so a short card's frame — the border, the fill, the ring — fills the row's height beside a taller neighbor instead of stopping at its content. `UniCardOption` gains `frame()`.
